# bitcoin-history-sync

Keeps a fork with a **rewritten-base history** up to date with its **upstream**,
putting new commits **on top** without breaking the base.

Built for a repository that reconstructs Bitcoin's early history (the November
2008 *preview*, v0.1.0/v0.1.3 and the SourceForge SVN era with **real author
identities** instead of `user@<UUID>`) and links it to all of `bitcoin/bitcoin`
up to today. But the script is generic: it works for any fork whose old era has
different SHAs than the upstream.

## The problem

If you rewrite the base of the history (the old commits' SHAs change), your
`master` **shares no SHAs** with the upstream. Then:

- `git pull` / `merge` doesn't apply (histories with no common ancestor).
- `git rebase` of the new commits **re-merges** the upstream's merge commits and
  produces **conflicts**.
- `git cherry-pick` **flattens** merges (loses PR commits and topology).

## The solution

Deterministic re-splice with **`git replace` (graft) + `git-filter-repo`**:
it does not merge anything, it only rewrites the *parent* pointers of the old era
toward the rewritten commits. As a result:

- ✅ **0 conflicts** (no content merge).
- ✅ preserves **author, committer and the EXACT merge topology** of upstream.
- ✅ **deterministic**: already-published SHAs don't change → the push is a
  *fast-forward* (only the new commits are added).

## Requirements

- `git`, `bash`, `flock`, and [`git-filter-repo`](https://github.com/newren/git-filter-repo)
  (`pip install --user git-filter-repo`).
- A **pristine mirror** of the upstream: `git clone --mirror <upstream> ~/git/bitcoin-mirror`.
- The **base repo** (`PUB`) with the real-id base on a branch (`BASE_REF`, e.g. `svn`)
  and the `origin` remote pointing to your fork.
- A **mapping file** (`MAP`): for each *raw* commit of the upstream's old era, its
  real-id equivalent in `BASE_REF`, one `RAW_SHA REALID_SHA` pair per line.
  (Generated by matching by *tree*: each upstream commit whose tree matches one in
  the base → its real-id SHA.)

## Usage

```sh
./bitcoin-history-sync.sh
```

Everything is configurable via environment (defaults under `$HOME`, no absolute
paths — user-agnostic):

| Variable   | Default                                  | What it is                               |
|------------|------------------------------------------|------------------------------------------|
| `MIRROR`   | `$HOME/git/bitcoin-mirror`               | `--mirror` clone of the upstream         |
| `PUB`      | `$HOME/git/bitcoin-svn-git-history`      | repo with the real-id base (`BASE_REF`)  |
| `MAP`      | `$HOME/git/.bitcoin-splice-map.txt`      | `RAW_SHA REALID_SHA` mapping             |
| `BASE_REF` | `svn`                                    | base branch in `PUB` (up to the link)    |
| `BRANCH`   | `master`                                 | branch to level/publish                  |
| `ORIGIN`   | `git -C "$PUB" remote get-url origin`    | push URL of the fork                     |

### cron

```cron
0 */6 * * * /path/to/bitcoin-history-sync.sh
```

> The push in cron needs an SSH key **without a passphrase** (the script uses
> `GIT_SSH_COMMAND="ssh -o BatchMode=yes"`).

## Notes

- Only `BRANCH` (`master`) is synced. The base branches/tags (e.g. `svn`,
  `svn-full`) stay frozen.
- Idempotent: if there's nothing new upstream, it does not push.
